1. Интуитивная аналогия: Бюро пропусков и экспертные отделы

Чтобы навсегда устранить путаницу между десятком похожих названий (AuthenticationManager, AuthenticationProvider, UserDetailsService, UserDetails), представим организацию службы безопасности крупного предприятия:

Компонент Spring Security Аналогия из реальной жизни Обязанности и зона ответственности
AuthenticationManager Директор бюро пропусков Лично не проверяет подлинность водяных знаков и не копается в архивах. Координирует процесс: принимает документ посетителя и передает его в нужный экспертный отдел.
AuthenticationProvider Экспертный отдел / Специалист Узкоспециализированный эксперт по конкретному типу документов. Умеет проверить паспорт с фото, электронную смарт-карту или отпечаток пальца.
DaoAuthenticationProvider Эксперт по связке «Логин + Пароль» Специалист, знающий регламент: «Сходи в картотеку кадров по имени сотрудника, достань досье и сравни отпечаток пароля на криптографическом приборе».
UserDetailsService Архивариус картотеки Знает, в каком шкафу (в какой таблице PostgreSQL) лежит досье сотрудника. Достает карточку по фамилии/логину. Пароли сам не проверяет — просто выдает данные.
UserDetails (AppPrincipal) Личное дело / Карточка сотрудника Контейнер данных: хэш пароля из базы, список допусков и прав (Authorities), флаги активности и блокировки.
PasswordEncoder Криптографический прибор Математический калькулятор. Сверяет введенный пароль с захешированным паролем из базы: matches(raw, hash).
SecurityContext Журнал дежурного / Временный бейдж Хранит информацию о том, кто прямо сейчас находится в здании и выполняет текущий HTTP-запрос.

2. Что такое AuthenticationManager и ProviderManager под капотом

В исходном коде Spring Security интерфейс AuthenticationManager содержит ровно один метод: 

package org.springframework.security.authentication;

import org.springframework.security.core.Authentication;
import org.springframework.security.core.AuthenticationException;

public interface AuthenticationManager {
    Authentication authenticate(Authentication authentication) throws AuthenticationException;
}
  • На вход: Неаутентифицированный объект Authentication (например, UsernamePasswordAuthenticationToken с сырыми логином и паролем, у которого флаг isAuthenticated() == false).
  • На выходе: Подтвержденный объект Authentication (с Principal, подтвержденными правами authorities, очищенным паролем и флагом isAuthenticated() == true).
  • При ошибке: Выбрасывается подкласс AuthenticationException (BadCredentialsException, DisabledException, LockedException).

ProviderManager — реализация по умолчанию

В 99% случаев реализацией интерфейса выступает класс ProviderManager. Внутри него хранится обычный список провайдеров: 

public class ProviderManager implements AuthenticationManager {
    private List<AuthenticationProvider> providers;
    // ...
}

При вызове authenticate() он в цикле опрашивает каждый провайдер:

  1. Вызывает provider.supports(authentication.getClass()).
  2. Если провайдер возвращает true, вызывается provider.authenticate(authentication).
  3. Если проверка успешна, цикл завершается, и готовый объект возвращается вызывающей стороне.

3. Что такое AuthenticationProvider и какие виды бывают

Интерфейс AuthenticationProvider — это компонент, в котором реализована конкретная механика проверки учетных данных: 

public interface AuthenticationProvider {
    Authentication authenticate(Authentication authentication) throws AuthenticationException;
    boolean supports(Class<?> authentication);
}
Провайдер Для чего применяется С какими компонентами работает
DaoAuthenticationProvider Классический вход по логину и паролю из базы данных (наш проект). UserDetailsService (загрузка из БД) + PasswordEncoder (BCrypt).
LdapAuthenticationProvider Вход через корпоративный каталог Active Directory / LDAP. LdapAuthenticator, LdapAuthoritiesPopulator.
JwtAuthenticationProvider Проверка цифровой подписи и claims токенов JWT (OAuth2 Resource Server). JwtDecoder, JwtAuthenticationConverter.
RememberMeAuthenticationProvider Вход по долгоживущей cookie "Запомнить меня". RememberMeServices, ключ подписи cookie.
AnonymousAuthenticationProvider Предоставляет анонимный контекст неавторизованным гостям. Константа роли ROLE_ANONYMOUS.

4. Пошаговая анатомия работы DaoAuthenticationProvider (5 этапов)

Когда в контроллере вызывается authenticationManager.authenticate(new UsernamePasswordAuthenticationToken(login, password)), провайдер DaoAuthenticationProvider выполняет строго 5 шагов:

  1. Шаг 1: Загрузка досье из БД (loadUserByUsername)
    Провайдер извлекает имя пользователя из токена и вызывает userDetailsService.loadUserByUsername(username). Сервис идет в таблицу users через JPA Repository и возвращает объект UserDetails (AppPrincipal). Если пользователь не найден — сразу выбрасывается UsernameNotFoundException.
  2. Шаг 2: Проверка системных статусов аккаунта (Account Status Checks)
    Провайдер проверяет 4 булевых флага:
    • isAccountNonLocked() — не заблокирован ли пользователь? (если false $\to$ LockedException);
    • isEnabled() — активен ли пользователь? (если false $\to$ DisabledException);
    • isAccountNonExpired() — не истек ли срок действия учетной записи? (если false $\to$ AccountExpiredException);
    • isCredentialsNonExpired() — не протух ли пароль? (если false $\to$ CredentialsExpiredException).
  3. Шаг 3: Сверка хэша пароля (passwordEncoder.matches)
    Провайдер берет сырой пароль от клиента и хэш из UserDetails.getPassword(), после чего вызывает: 
    if (!passwordEncoder.matches(rawPassword, userDetails.getPassword())) {
    throw new BadCredentialsException("Неверный логин или пароль");
}
  4. Шаг 4: Стирание пароля из памяти (Credentials Erasing)
    В целях безопасности сырой пароль удаляется из объекта токена (credentials = null), чтобы он случайно не утек в логи, дампы кучи (Heap Dump) или трассировку стека.
  5. Шаг 5: Создание подтвержденного объекта Authentication
    Провайдер конструирует новый токен с тремя параметрами: new UsernamePasswordAuthenticationToken(principal, null, userDetails.getAuthorities()). У этого токена флаг isAuthenticated() равен true.

6. Зачем пишется отдельный метод @Bean для AuthenticationManager

Один из самых частых вопросов: «Зачем в SecurityConfiguration объявлять отдельный бин менеджера, если Spring Security и так уже настроен?».

Проблема скрытого бина (NoSuchBeanDefinitionException)

По умолчанию Spring Security создает экземпляр AuthenticationManager внутри своих фильтров исключительно для внутренних нужд и не экспортирует его в ApplicationContext в качестве публичного Spring-бина.

Если в AuthController попытаться заинжектить его через конструктор: 

@RestController
@RequiredArgsConstructor
public class AuthController {
    // БЕЗ МЕТОДА @Bean БУДЕТ ОШИБКА ПРИ СТАРТЕ:
    // Parameter 0 of constructor in AuthController required a bean of type 'AuthenticationManager' that could not be found.
    private final AuthenticationManager authenticationManager;
}
Вывод

Метод с аннотацией @Bean пишется ровно для того, чтобы «выставить» менеджер наружу в общий контейнер внедрения зависимостей (IoC Container), позволив внедрять его в любые контроллеры и сервисы.

7. Два канонических способа объявления бина в Spring Security 6

Способ Фрагмент кода Как работает и когда применять
Способ 1 (Рекомендуемый): Через AuthenticationConfiguration 
@Bean
public AuthenticationManager authenticationManager(
        AuthenticationConfiguration authConfig) throws Exception {
    return authConfig.getAuthenticationManager();
}
 Стандарт Spring Boot 3. Spring автоматически находит зарегистрированные в проекте бины UserDetailsService и PasswordEncoder, под капотом собирает DaoAuthenticationProvider и отдает готовый ProviderManager.
Способ 2 (Явный): Ручная сборка ProviderManager 
@Bean
public AuthenticationManager authenticationManager(
        UserDetailsService userDetailsService,
        PasswordEncoder passwordEncoder) {
    DaoAuthenticationProvider provider = new DaoAuthenticationProvider();
    provider.setUserDetailsService(userDetailsService);
    provider.setPasswordEncoder(passwordEncoder);
    return new ProviderManager(provider);
}
 Полный контроль. Применяется, когда в приложении несколько источников входа (например, база данных + корпоративный LDAP) и нужно передать список провайдеров new ProviderManager(daoProvider, ldapProvider).

8. Что скрывается внутри AuthenticationConfiguration.java

Если открыть исходный код класса AuthenticationConfiguration.java, можно увидеть, как фреймворк выполняет автоматическую связку: 

@Bean
public static InitializeUserDetailsBeanManagerConfigurer initializeUserDetailsBeanManagerConfigurer(...) {
    // Ищет в контексте бин типа UserDetailsService
    return new InitializeUserDetailsBeanManagerConfigurer(context);
}

@Bean
public static InitializeAuthenticationProviderBeanManagerConfigurer initializeAuthenticationProviderBeanManagerConfigurer(...) {
    // Ищет PasswordEncoder и связывает его с UserDetailsService в DaoAuthenticationProvider
    return new InitializeAuthenticationProviderBeanManagerConfigurer(context);
}

9. Где искать в официальной документации Spring (docs.spring.io)

Официальный портал: docs.spring.io/spring-security/reference/.

Критическое разделение: Authentication vs Authorization

• Authentication (Аутентификация — /servlet/authentication/...): Отвечает на вопрос «Кто ты?». Ищи здесь всё про логин, пароли, токены, AuthenticationManager, DaoAuthenticationProvider, UserDetailsService, PasswordEncoder.
• Authorization (Авторизация — /servlet/authorization/...): Отвечает на вопрос «Что тебе разрешено делать?». Ищи здесь всё про роли, права доступа, @PreAuthorize, requestMatchers(), ошибки 403 Forbidden.

10. Как смотреть документацию и исходники прямо в IntelliJ IDEA

В 1С нажатие Ctrl + F1 открывает Синтакс-помощник. В Java документация устроена двухуровнево: скомпилированный байткод .jar и исходники с комментариями -sources.jar.

  1. Горячая клавиша Quick Documentation (Ctrl + Q / F1):
    Поставьте курсор на имя метода или класса (например, getAuthenticationManager) и нажмите Ctrl + Q. IDEA откроет всплывающее окно с примерами кода из Javadoc.
  2. Кнопка "Download Sources" (Скачать исходники):
    Если при переходе в класс открывается декомпилированный код без комментариев, нажмите на желтой полосе вверху кнопку "Download Sources". Gradle скачает оригинальные Java-файлы с комментариями создателей фреймворка.

11. Как комфортно читать документацию на английском с уровнем A2+/B1

Технический английский в документации Spring сухой, структурированный и состоит из 300–400 повторяющихся терминов.

4-шаговая методика диагонального чтения

  1. Шаг 1: Смотрите на схемы и код (70% понимания). Пролистайте страницу сразу до диаграммы или листинга Java. Названия методов и типов объясняют суть лучше любого текста.
  2. Шаг 2: Читайте информационные блоки (Callouts). Блоки Tip (рекомендация), Note (важное примечание) и Warning / Deprecated (устаревший код) содержат квинтэссенцию страницы.
  3. Шаг 3: Читайте только первое предложение каждого абзаца. В англоязычной технической литературе главное утверждение всегда идет в первом предложении (Topic Sentence). Если оно не про вашу проблему — пропускайте весь абзац.
  4. Шаг 4: Используйте двуязычный переводчик (Immersive Translate). Расширение для браузера, выводящее русский перевод под оригинальной английской строкой и не ломающее код.

Памятка для быстрой самопроверки

1. AuthenticationManager координирует провайдеров.
2. DaoAuthenticationProvider связывает UserDetailsService и PasswordEncoder.
3. UserDetailsService только читает из базы и не проверяет пароли.
4. Бин @Bean public AuthenticationManager нужен для инжекта в контроллер.
